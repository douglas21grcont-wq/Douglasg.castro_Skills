Teste prático: como usar Specs para automatizar código com auditoria paralela

1
Spec (Você)

Você documenta o que precisa ser feito. Exemplo real do Portal DG:

Problema: Telas de Acompanhamento de Projetos quebram em mobile (≤768px)
Objetivo: 100% responsividade em viewport mobile
Regras: Design system azul/claro, botões ≥44px, tabelas com scroll interno
Critérios: 8 checklist items (veja artifact da Spec)

✓ Spec está documentada (veja artifact anterior)

2
Plano (Opus)

Opus lê a Spec e divide em 10 etapas executáveis:

Etapa 1: Auditar estado atual dos 4 arquivos PHP
Etapa 2: Mapear queries responsive já existentes
Etapa 3: Criar @media (max-width: 768px) em index.php
Etapa 4: Responsivizar tabelas (overflow-x: auto)
Etapa 5: Ajustar tipografia: 13px → 12px em mobile
Etapa 6: Redimensionar topbar (logo, botões)
Etapa 7: Fazer o mesmo para projeto.php
Etapa 8: Aplicar a editar.php
Etapa 9: Verificar gantt.php (gráfico Gantt responsivo?)
Etapa 10: Testar em 4 breakpoints reais

3
Executa (Sonnet 5)

Sonnet 5 aplica cada etapa. Exemplo (Etapa 3):

/* Acompanhamento_de_projetos/index.php */ @media (max-width: 768px) { .hub-main { padding: 28px 16px 72px; } .topbar { padding: 0 16px; gap: 10px; } .topbar-title { font-size: 12px; } table { font-size: 12px; } table { overflow-x: auto; display: block; } tbody { overflow-x: auto; } }

Sonnet edita os 4 arquivos, respeitando: design system tokens + sem quebra de PHP + 0 regressões desktop.

4
Audita (Haikus em Paralelo)

Haiku 1: Tokens CSS Haiku 2: Responsividade Haiku 3: Acessibilidade

Haiku 1 — Auditoria de Tokens CSS

✓ PASS: Cores da Spec vêm de --blue (#2563eb), não hardcoded
✓ PASS: Espaçamento usa var(--radius): 8px em mobile
✓ PASS: Poppins carregado via Google Fonts

Haiku 2 — Auditoria de Responsividade

✓ PASS: @media queries no breakpoint exato (768px)
✓ PASS: Tabelas com overflow-x: auto (não scroll page)
✓ PASS: Sem regressão desktop: @media não afeta ≥769px

Haiku 3 — Auditoria de Acessibilidade

✓ PASS: Botões: altura 44px (Apple HIG)
✓ PASS: Touch targets espaçados 8px+
✓ PASS: Tipografia 12px mín (readability)

5
Relata (Haiku — Resumo Final)

Haiku gera relatório final consolidando auditoria:

✓ Topbar sem scroll horizontal
✓ Tabelas scroll interno
✓ Cards empilham
✓ Inputs confortáveis

• Compatibilidade: iOS 12+ ✓, Android 90+ ✓
• Pronto para deploy

O que fazer com isso?

Agora você tem 2 caminhos:

Caminho A: Skill + Agente (Automatizado)
Criar uma skill /spec-driven que:
• Captura a Spec (manual, você escreve)
• Dispara agente Opus para plano
• Dispara agente Sonnet para execução
• Dispara N agentes Haiku para auditoria paralela
• Consolida relatório final
Caminho B: Agente Único (Mais simples)
Um agente spec-executor que:
• Recebe a Spec + plano (você traz prontos)
• Ele orquestra Sonnet + Haikus internamente
• Devolve um relatório final

🎓
Resumo: Por que Specs funcionam para você

  • ✓ Sem ping-pong: Agente sabe exatamente o que fazer antes de começar
  • ✓ Auditoria automática: Haikus validam contra Spec em paralelo
  • ✓ Rastreabilidade: Cada mudança é validada contra critérios escritos
  • ✓ Portal DG: Especialmente útil para regras complexas (RBAC, deploy, responsividade)
  • ✓ Dois passos depois: Handoff captura lições aprendidas (não repetir erros)
  • ✓ Facilita código review: Basta comparar resultado com Spec
